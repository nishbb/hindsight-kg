# Related work

Checked on 2026-11-16 with web search plus metadata verification against arXiv abstract pages, NCBI E-utilities (PubMed/PMC esummary), the bioRxiv API, and the GitHub API. Every entry below was opened or its metadata was retrieved from the primary index. Authors are abbreviated to the first few listed.

**Conclusion of the check:** no prior work we found tests H1, H2 and H3 together. Closest pieces: tabular models of ClinVar reclassification (RENOVO; a 2025 thesis), a GCN evaluated on one year of ClinVar label changes (PathoGN), GNN or multi-agent LLM error detection on knowledge graphs with *synthetic* noise (KGTtm, CCA, MAKGED, Model Garbage Collection), and graph-RAG systems that assume the graph is correct (G-Retriever, the NVIDIA/Neo4j STaRK-Prime pipeline, BioGraphRAG). What is new here is the combination: (1) using ClinVar's own archived history as a prospective, label-free ground truth for knowledge graph "garbage", (2) a strict time-T leakage protocol for every node, edge and feature, (3) an evidence-retrieving agent that spends tool calls according to conformal uncertainty, and (4) a test of whether trust-based cleaning helps downstream link prediction and graph-RAG.

## Differentiation statement (for the paper)

Prior work either (a) predicts variant reclassification with tabular features and no graph, (b) detects KG errors that were injected synthetically, or (c) does graph-RAG on graphs assumed to be correct. kg-gc treats a genotype-phenotype KG built at time T as the object of study, uses later ClinVar releases as real prospective labels for which edges were garbage, asks whether graph structure adds signal beyond the ClinVar metadata that curators already see, and tests whether an uncertainty-aware evidence agent and trust-based cleaning help. If the graph adds nothing beyond tabular metadata, that is itself a useful negative result for the "GNNs for KG quality" agenda, and we will report it.
